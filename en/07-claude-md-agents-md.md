# Chapter 07 — `CLAUDE.md` and `AGENTS.md`

## What they are

Plain markdown files loaded into context **at the start of every session**. Persistent project memory.

- `CLAUDE.md` → Claude Code specific
- `AGENTS.md` → an open standard shared by Codex, Cursor, Gemini CLI, Aider, Jules, and others

## `CLAUDE.md` hierarchy

From broadest to most specific (more specific loads later → higher influence):

| Scope | Path | Purpose |
|---|---|---|
| Managed policy | Linux: `/etc/claude-code/CLAUDE.md` · macOS: `/Library/Application Support/ClaudeCode/CLAUDE.md` | Org policy |
| User | `~/.claude/CLAUDE.md` | Personal preferences, all projects |
| Project | `./CLAUDE.md` or `./.claude/CLAUDE.md` | Team rules — commit to git |
| Local | `./CLAUDE.local.md` | Personal to this project — gitignore it |

All of them are **concatenated**, not overridden.

Files in subdirectories (`src/api/CLAUDE.md`) load when Claude reads a file in that directory.

## Getting started

```bash
claude
> /init
```

Claude analyzes the codebase and writes a starting `CLAUDE.md`. Refine from there.

Check what actually loaded:

```
/context     # under "Memory files"
/memory      # open and edit
```

## Three writing principles (emphasize these in class)

### 1. Size — under 200 lines

A bigger file means more context and *less* adherence. If it grows, split it into `.claude/rules/` with `paths`.

### 2. Structure — headers and bullets

```markdown
# Project

## Commands
## Architecture
## Conventions
## Gotchas
```

### 3. Specificity — write things you can verify

| ❌ Vague | ✅ Specific |
|---|---|
| "Format code properly" | "Use 2-space indentation" |
| "Test your changes" | "Run `npm test` before committing" |
| "Keep files organized" | "API handlers live in `src/api/handlers/`" |

## The golden rule of content

> **Write what Claude cannot figure out from the code itself.**

❌ Don't write: folder structure, dependency lists, general architecture — Claude gets that from one `ls`.
✅ Do write: traps, historical decisions, surprising behavior, the *why*.

## A `CLAUDE.md` template

```markdown
# Payments Service

Node 20 + Express + PostgreSQL. Handles all Stripe integration.

## Commands
- `npm run dev`     — dev server, port 3000
- `npm test`        — Jest, must pass before commit
- `npm run db:migrate` — apply migrations
- `npm run lint:fix`

## Conventions
- TypeScript strict. No `any` — use `unknown` and narrow.
- 2-space indent, single quotes, trailing commas.
- Errors: throw `AppError` from `src/errors.ts`, never bare `Error`.
- Money is always integer cents. Never float.

## Architecture
- `src/api/handlers/` — HTTP layer only, no business logic
- `src/services/`     — business logic, no HTTP types
- `src/db/`           — Drizzle queries only

## Gotchas
- `StripeWebhookHandler` must stay idempotent — Stripe retries.
- Integration tests need a local Redis. `docker compose up -d redis` first.
- Never edit `src/generated/` — regenerated by `npm run codegen`.
- The `legacy_orders` table is read-only. New writes go to `orders`.

## Workflow
- Branch from `develop`, not `main`.
- Conventional Commits.
- Never push to `main` directly.
```

## `AGENTS.md`

An open standard (agents.md) read by 20+ AI tools. If your team uses several tools, write one file.

**Claude Code does not read `AGENTS.md` directly.** Two ways around it:

### Option 1 — import (recommended)

`CLAUDE.md`:

```markdown
@AGENTS.md

## Claude Code

Use plan mode for changes under `src/billing/`.
```

### Option 2 — symlink

```bash
ln -s AGENTS.md CLAUDE.md
```

(On Windows this needs Administrator rights — use option 1.)

## Import syntax

```markdown
See @README for project overview and @package.json for npm commands.

- git workflow @docs/git-instructions.md
- personal prefs @~/.claude/my-project-instructions.md
```

- Max depth of 4 hops
- A path inside backticks — `` `@README` `` — is not imported, it stays literal
- Imported files **also load into context** — splitting files organizes your instructions, it does not reduce context

## `.claude/rules/` for large projects

```
your-project/
├── .claude/
│   ├── CLAUDE.md
│   └── rules/
│       ├── testing.md
│       ├── api-design.md
│       └── security.md
```

Path-scoped rules load only when Claude reads a matching file:

```markdown
---
paths:
  - "src/api/**/*.ts"
---

# API Development Rules

- All API endpoints must include input validation
- Use the standard error response format
- Include OpenAPI documentation comments
```

This is the best way to keep context small in a monorepo.

## Auto memory

Claude also takes its own notes — from your corrections. Stored at:

```
~/.claude/projects/<project>/memory/
├── MEMORY.md          # index, loaded every session
└── <topic>.md         # read on demand
```

Manage with `/memory`. Disable:

```json
{ "autoMemoryEnabled": false }
```

## Important: `CLAUDE.md` is not enforcement

Its content is delivered as a *user message*, not as a system prompt. Claude tries to follow it but compliance isn't guaranteed.

If something **must** happen at a specific point (for example, lint before every commit) → [write a hook](10-hooks-and-commands.md), not a `CLAUDE.md` line.

## Troubleshooting

```
/context    # did the file load?
/memory     # edit
/doctor     # proposes trims for an oversized CLAUDE.md
```

If it isn't being followed:
1. Did it actually load? (`/context`)
2. Is the instruction specific enough?
3. Is another file contradicting it?
