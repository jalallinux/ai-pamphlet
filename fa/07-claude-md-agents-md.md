# فصل ۰۷ — `CLAUDE.md` و `AGENTS.md`

## چیستند

فایل markdown ساده‌ای که **در ابتدای هر جلسه** داخل context بارگذاری می‌شود. حافظهٔ دائمی پروژه.

- `CLAUDE.md` → مخصوص Claude Code
- `AGENTS.md` → استاندارد باز، مشترک بین Codex, Cursor, Gemini CLI, Aider, Jules و بقیه

## سلسله‌مراتب `CLAUDE.md`

از عام به خاص (خاص‌تر دیرتر خوانده می‌شود → اولویت بیشتر):

| اسکوپ | مسیر | کاربرد |
|---|---|---|
| Managed policy | Linux: `/etc/claude-code/CLAUDE.md` · macOS: `/Library/Application Support/ClaudeCode/CLAUDE.md` | سیاست سازمان |
| کاربر | `~/.claude/CLAUDE.md` | ترجیحات شخصی، همهٔ پروژه‌ها |
| پروژه | `./CLAUDE.md` یا `./.claude/CLAUDE.md` | قوانین تیم — commit در git |
| محلی | `./CLAUDE.local.md` | شخصی برای این پروژه — در `.gitignore` |

همه به هم **الحاق** می‌شوند، نه اینکه یکدیگر را override کنند.

فایل‌های زیرپوشه‌ها (`src/api/CLAUDE.md`) وقتی بارگذاری می‌شوند که Claude فایلی در آن پوشه بخواند.

## شروع سریع

```bash
claude
> /init
```

Claude کدبیس را تحلیل می‌کند و یک `CLAUDE.md` اولیه می‌سازد. از آنجا اصلاح کنید.

بررسی اینکه چه چیزی واقعاً بارگذاری شده:

```
/context     # زیر بخش Memory files
/memory      # باز کردن و ویرایش
```

## سه اصل نوشتن (این بخش را در کلاس تأکید کنید)

### ۱. اندازه — زیر ۲۰۰ خط

فایل بزرگ‌تر = context بیشتر + پیروی کمتر. اگر رشد کرد، به `.claude/rules/` با `paths` تقسیم کنید.

### ۲. ساختار — تیتر و بولت

```markdown
# Project

## Commands
## Architecture
## Conventions
## Gotchas
```

### ۳. دقت — قابل تأیید بنویسید

| ❌ مبهم | ✅ دقیق |
|---|---|
| «کد را تمیز فرمت کن» | «تورفتگی ۲ فاصله» |
| «تست بزن» | «قبل از commit `npm test` را اجرا کن» |
| «فایل‌ها را مرتب نگه دار» | «API handler ها در `src/api/handlers/`» |

## قانون طلایی محتوا

> **چیزی را بنویسید که Claude نمی‌تواند از خود کد بفهمد.**

❌ ننویسید: ساختار پوشه‌ها، لیست dependency ها، معماری کلی — Claude با یک `ls` می‌فهمد.
✅ بنویسید: تله‌ها، تصمیم‌های تاریخی، رفتارهای غیرمنتظره، «چرا»ها.

## قالب `CLAUDE.md`

```markdown
# Payments Service

Node 20 + Express + PostgreSQL. Handles all Stripe integration.

## Commands
- `npm run dev`     — dev server, port 3000
- `npm test`        — Jest, must pass before commit
- `npm run db:migrate` — apply migrations
- `npm run lint:fix`

## Conventions
- TypeScript strict. No `any` — use `unknown` and narrow.
- 2-space indent, single quotes, trailing commas.
- Errors: throw `AppError` from `src/errors.ts`, never bare `Error`.
- Money is always integer cents. Never float.

## Architecture
- `src/api/handlers/` — HTTP layer only, no business logic
- `src/services/`     — business logic, no HTTP types
- `src/db/`           — Drizzle queries only

## Gotchas
- `StripeWebhookHandler` must stay idempotent — Stripe retries.
- Integration tests need a local Redis. `docker compose up -d redis` first.
- Never edit `src/generated/` — regenerated by `npm run codegen`.
- The `legacy_orders` table is read-only. New writes go to `orders`.

## Workflow
- Branch from `develop`, not `main`.
- Conventional Commits.
- Never push to `main` directly.
```

## `AGENTS.md`

استاندارد باز (agents.md) که بیش از ۲۰ ابزار AI می‌خوانند. اگر تیم شما چند ابزار مختلف استفاده می‌کند، یک فایل بنویسید.

**Claude Code مستقیماً `AGENTS.md` را نمی‌خواند.** دو راه:

### راه ۱ — import (توصیه‌شده)

`CLAUDE.md`:

```markdown
@AGENTS.md

## Claude Code

Use plan mode for changes under `src/billing/`.
```

### راه ۲ — symlink

```bash
ln -s AGENTS.md CLAUDE.md
```

(روی ویندوز نیاز به Administrator دارد — از راه ۱ استفاده کنید.)

## سینتکس import

```markdown
See @README for project overview and @package.json for npm commands.

- git workflow @docs/git-instructions.md
- personal prefs @~/.claude/my-project-instructions.md
```

- حداکثر ۴ سطح تودرتو
- مسیر داخل backtick — `` `@README` `` — import نمی‌شود، متن می‌ماند
- فایل import شده **هم در context بارگذاری می‌شود** — تقسیم فایل، context را کم نمی‌کند، فقط سازمان‌دهی می‌کند

## `.claude/rules/` برای پروژه‌های بزرگ

```
your-project/
├── .claude/
│   ├── CLAUDE.md
│   └── rules/
│       ├── testing.md
│       ├── api-design.md
│       └── security.md
```

قانون محدود به مسیر — فقط وقتی Claude فایل منطبق را می‌خواند بارگذاری می‌شود:

```markdown
---
paths:
  - "src/api/**/*.ts"
---

# API Development Rules

- All API endpoints must include input validation
- Use the standard error response format
- Include OpenAPI documentation comments
```

این بهترین راه کاهش context در monorepo است.

## Auto Memory

Claude خودش هم یادداشت برمی‌دارد — از تصحیح‌های شما. ذخیره در:

```
~/.claude/projects/<project>/memory/
├── MEMORY.md          # فهرست، هر جلسه بارگذاری می‌شود
└── <topic>.md         # بر حسب نیاز خوانده می‌شود
```

مدیریت با `/memory`. خاموش کردن:

```json
{ "autoMemoryEnabled": false }
```

## نکتهٔ مهم: `CLAUDE.md` اجبار نیست

محتوای آن به‌عنوان *پیام کاربر* تحویل می‌شود، نه system prompt. Claude سعی می‌کند پیروی کند اما تضمینی نیست.

اگر چیزی **باید** حتماً در نقطهٔ مشخصی اجرا شود (مثلاً lint قبل از هر commit) → [Hook بنویسید](10-hooks-and-commands.md)، نه `CLAUDE.md`.

## اشکال‌یابی

```
/context    # آیا فایل بارگذاری شده؟
/memory     # ویرایش
/doctor     # پیشنهاد کوتاه‌سازی CLAUDE.md
```

اگر پیروی نمی‌کند:
1. آیا واقعاً بارگذاری شده؟ (`/context`)
2. آیا دستور به‌قدر کافی دقیق است؟
3. آیا دستور متناقضی در فایل دیگری هست؟
